# UA Alerts

UA Alerts — користувацька інтеграція Home Assistant для рівнів повітряної тривоги в Україні зі станами `clear`, `yellow`, `red`, загрозами, охопленням території та вимірюванням лагу появи подій у Home Assistant.

Джерело даних — raw-потік `alerts.in.ua` без токена через Ubilling:

`https://ubilling.net.ua/aerialalerts/?source=aiu&raw`

## Ідентифікатори проєкту

- Назва: **UA Alerts**
- Domain: `ua_alerts`
- Каталог інтеграції: `custom_components/ua_alerts/`
- Репозиторій: `gamba69/home-assistant-ua-alerts`
- Поточний реліз: **0.1.23**

## Основні можливості

- одна Config Entry на територію, одночасно можна додати кілька територій;
- єдиний runtime на весь domain: один HTTP-запит і один розбір відповіді на цикл незалежно від кількості територій;
- глобальні інтервали polling/stale, типово 3 с / 15 с;
- рівень тривоги визначається лише за `alert_level` джерела;
- коректна адміністративна ієрархія `область → район → громада`;
- для районів та областей розрізняється повне, часткове і змішане охоплення;
- загрози об'єднуються та дедуплікуються для всіх застосовних рівнів ієрархії;
- окремі компактні end-to-end вимірювання лагу тривоги та нової загрози;
- EN / RU / UK локалізація;
- повний вбудований довідник територій і лише ручне його оновлення;
- короткі стабільні entity_id на основі UID території;
- структура репозиторію готова для HACS.

## Встановлення

### Через HACS як custom repository

1. Додайте `gamba69/home-assistant-ua-alerts` у HACS як користувацький репозиторій категорії **Integration**.
2. Встановіть **UA Alerts**.
3. Перезапустіть Home Assistant.
4. Відкрийте **Налаштування → Пристрої та служби → Додати інтеграцію** і знайдіть **UA Alerts**.
5. Оберіть територію через **Пошук** або **Дерево**.

### Вручну

Скопіюйте `custom_components/ua_alerts/` до `/config/custom_components/ua_alerts/`, перезапустіть Home Assistant і додайте інтеграцію через інтерфейс.

## Вибір території

У пакеті вбудовано знімок довідника з 1607 територій: 25 територій рівня області, 122 райони, 1458 громад і два міста зі спеціальним статусом. Пошук приймає назву, низку поширених/історичних варіантів та UID `alerts.in.ua`. Дерево дозволяє послідовно вибрати область/місто, рівень, район і громаду.

Довідник **ніколи не оновлюється автоматично**. Оновлення запускається лише користувачем через **Налаштувати → Оновити довідник територій**. Успішно завантажена версія зберігається локально; невдале оновлення не замінює останню валідну копію.

## Адміністративне успадкування та часткове охоплення

Тривога на батьківській території діє на всіх нащадків. Тому вибрана громада перевіряє власний UID, UID району та UID області; вибраний район — власний UID та UID області. Максимальний рівень має пріоритет: `red > yellow > clear`.

Зворотний напрямок не означає повну тривогу. Якщо тривога є лише в одній громаді, увесь район не стає «повністю червоним». Для районів та областей існує окремий сенсор охоплення:

- `none` — тривоги немає;
- `full` — тривога діє на всю вибрану територію;
- `partial` — активна лише частина дочірніх територій;
- `mixed` — вся територія має один рівень, а частина дочірніх територій — вищий.

Наприклад, район повністю `yellow`, а одна громада `red`: підсумковий рівень району — `red`, охоплення — `mixed`, `full_level_code=yellow`, `partial_level_code=red`.

## Сутності

Для громади/міста створюються одинадцять сутностей, включно з двома редагованими глобальними параметрами; для району/області — дванадцята сутність охоплення:

| Entity ID | Призначення |
| --- | --- |
| `sensor.ua_<uid>_level` | Рівень тривоги; в атрибутах лише scope та зрозуміле джерело території |
| `sensor.ua_<uid>_coverage` | Лише район/область: `none/full/partial/mixed` і `full_level_code` / `partial_level_code` |
| `binary_sensor.ua_<uid>_alert` | Чи активна повітряна тривога |
| `sensor.ua_<uid>_threats` | Активні `threat_codes` і детальний список `threats` |
| `binary_sensor.ua_<uid>_source` | Доступність/свіжість джерела |
| `sensor.ua_<uid>_last_alert_duration` | Тривалість у компактному `MM:SS`, `H:MM:SS` або `Dд HH:MM:SS`; секунди в `duration_seconds` |
| `sensor.ua_<uid>_last_alert_level` | Максимальний рівень останньої повністю спостереженої завершеної тривоги |
| `sensor.ua_<uid>_last_alert_lag` | Лаг початку останньої нової тривоги до першого спостереження HA |
| `sensor.ua_<uid>_last_threat_lag` | Лаг появи останньої нової загрози до першого спостереження HA |
| `sensor.ua_<uid>_health` | Зведений стан даних |

Стабільні коди рівня: `clear`, `yellow`, `red`. Коди охоплення: `none`, `full`, `partial`, `mixed`.

Підтримувані коди загроз: `tactic_aircraft_activity`, `strategic_aircraft_activity`, `mig31k_departure`, `ballistic_missiles`, `cruise_missiles`, `unspecified_missiles`, `drones`, `guided_aerial_bombs`, `air_defense`, `unknown`.

## Лаг

`last_alert_lag` вимірюється лише при валідному переході `clear → yellow/red` як різниця між `Alert.started_at` і часом першого snapshot, де Home Assistant побачив нову тривогу. `last_threat_lag` аналогічно вимірює нову загрозу за `Threat.started_at`. Значення фіксуються та зберігаються в `.storage`.

Від 1 секунди лаг показується цілими секундами; нижче секунди — з точністю до двох знаків. Це вимірювання, а не оцінка якості джерела, тому вони не переводять `health` у `delayed`.

Зайві атрибути прибрано: рівень тривоги більше не дублює власне значення/possible-коди/UID; охоплення залишає тільки `full_level_code` і `partial_level_code`; загрози — тільки `threat_codes` і `threats`. `last_alert_level` не має власних атрибутів.

## Події

Інтеграція публікує:

- `ua_alert_level_changed`;
- `ua_alert_threats_changed`;
- `ua_alert_source_availability_changed`.

## Відмови джерела

Помилка одного опитування не означає `clear`: останній валідний snapshot зберігається. Після перевищення stale timeout операційні сутності стають unavailable, а `source_available` вимикається. Перший успішний запит відновлює роботу.

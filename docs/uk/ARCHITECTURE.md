# Архітектура

## Загальна схема

UA Alerts побудована навколо **одного runtime на весь domain** та окремих легких coordinator для кожної вибраної території. Кількість Config Entry не збільшує кількість запитів: один raw snapshot завантажується та розбирається один раз, після чого використовується всіма територіями.

## Основні модулі

- `runtime.py` — єдиний HTTP polling loop, серіалізація запитів, свіжість джерела та спільний parsed snapshot.
- `models.py` — валідація/розбір джерела та чиста логіка тривог, загроз, ієрархії та latency.
- `coordinator.py` — обчислює стан однієї території, відстежує переходи та публікує оновлення/події HA.
- `sensor.py`, `binary_sensor.py` — сутності Home Assistant.
- `catalog.py`, `catalog_parser.py`, `catalog_search.py` — вбудований довідник, ручне оновлення, пошук і дерево.
- `config_flow.py` — додавання території та спільні налаштування polling/stale.
- `latency_storage.py` — збереження останніх вимірювань затримки тривоги й загрози за UID.
- `health.py` — компактний стан якості даних.
- `entity_ids.py` — короткі UID-based entity_id і безпечна міграція старих автоматичних назв.

## Життєвий цикл runtime

Перша Config Entry створює `UAAlertsRuntime`, інші реєструються в тому самому екземплярі. Остання вивантажена Entry зупиняє runtime. Окремі asyncio-lock захищають lifecycle та HTTP-запити, тому паралельних polling loop і одночасних fetch немає.

Успішний цикл виконує один GET, перевіряє payload, фіксує єдиний `received_at`, один раз парсить raw, атомарно замінює спільний snapshot та сповіщає всі coordinators.

Помилка опитування не означає `clear`: останній валідний snapshot зберігається до перевищення stale timeout.

## Адміністративна ієрархія

Успадкування вниз є прямим: тривога області діє на її райони та громади, тривога району — на його громади. Для громади враховуються власний UID + район + область. Для району власний UID + область визначають повне охоплення.

Агрегація вгору має іншу семантику: тривога однієї громади не робить увесь район повністю тривожним. Для районів та областей активність дочірніх територій формує **часткове охоплення**. Сенсор охоплення має стани `none`, `full`, `partial`, `mixed`, а сенсор рівня показує максимальний рівень будь-де всередині вибраної території.

## Рівні та загрози

Враховуються лише активні записи `air_raid`. `alert_level` має бути `yellow` або `red`; рівень не виводиться з тексту чи часових полів. Для кількох застосовних записів діє пріоритет `red > yellow`.

Загрози з усіх застосовних full/partial записів об'єднуються та дедуплікуються. Відомі коди локалізуються для інтерфейсу, сирі коди залишаються в атрибутах. Невідомий майбутній код не відкидається.

## Семантика latency

Затримка тривоги вимірюється лише після валідного baseline та на реальному переході `clear -> active`:

`Alert.started_at -> received_at першого snapshot, де HA побачив тривогу`.

Затримка загрози вимірюється для нового екземпляра `(threat_type, started_at)`:

`Threat.started_at -> received_at першого snapshot з цією загрозою`.

Значення фіксуються, зберігаються за UID та відновлюються після перезапуску. Якщо HA запускається під час уже активної тривоги/загрози, це створює baseline, а не хибну велику затримку.

## Ідентичність сутностей

Entity ID будуються за стабільним UID території, наприклад `sensor.ua_31_level`. `unique_id` не змінюються між релізами. Міграція скорочує лише незмінені старі автоматичні ID та зберігає ручні перейменування. Повторна міграція після створення платформ обробляє старі ID, відновлені Home Assistant з deleted registry.

## Політика довідника

У пакет входить повний snapshot довідника. Автоматичного оновлення немає. Оновлення запускається вручну з options flow; помилка не замінює останню валідну збережену версію.

## Помилки та діагностика

Операційні сутності стають unavailable при stale джерелі або невалідних даних вибраної території. `data_health` залишається доступним і показує `normal`, `delayed`, `source_error`, `data_error`. `delayed` стосується лише повільної HTTP-відповіді; end-to-end затримки тривог і загроз є вимірюваннями та самі по собі не вважаються помилкою.

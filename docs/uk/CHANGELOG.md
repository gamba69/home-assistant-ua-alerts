# Історія змін

## 0.1.20
- Діагностичні `Затримка тривоги` / `Затримка загрози` замінено звичайними state-сенсорами `Затримка останньої тривоги` та `Затримка останньої загрози`; entity registry мігрується без втрати накопичених вимірювань.
- Додано `Тривалість останньої тривоги` і `Рівень останньої тривоги` — максимальний жовтий/червоний рівень останньої повністю спостереженої завершеної тривоги.
- Lifecycle поточної тривоги зберігається в `.storage`, тому нормальна тривога переживає перезапуск HA та коректно завершується за достовірним `clear`; stale/помилки тривогу не закривають.
- Якщо HA вперше запустився вже посеред невідомої активної тривоги, тривалість і максимальний рівень для неї навмисно не вигадуються.

## 0.1.19
- Виправлено HA 2026.9 device-registry тести після видалення `DeviceEntry.translation_key`.
- Синхронізовано версію та публічну документацію; до кореневого README додано короткий опис проєкту.

## 0.1.18
- HA regression-тести оновлено під актуальні API 2026.9; перевірка версії більше не прив'язана до конкретного patch-релізу.
- Python-константу `VERSION` синхронізовано з manifest.

## 0.1.17
- Виправлено порядок ключів manifest для Hassfest і оголошено config-entry-only schema.
- Project tests переведено на Python 3.14; pip cache прив'язано до `requirements_test.txt`.

## 0.1.16

- Формулювання config flow зроблено нейтральним: вручну оновлений збережений довідник більше не називається «вбудованим».
- Підготовлено перший публічний GitHub/HACS-реліз без зміни робочої семантики тривог.
- Додано MIT License і тримовну документацію `docs/en`, `docs/ru`, `docs/uk`; кореневі README/CHANGELOG/ARCHITECTURE/TESTING зроблено навігаційними за зразком Vacuum Schedule.
- CI розділено на `hacs.yaml`, `hassfest.yaml`, `tests.yaml`; додано JSON/YAML validation і заборону згенерованих `.patch`.
- У `hacs.json` додано `render_readme: true`; тести розширено перевіркою публічної структури репозиторію.
- Додано окрему документацію з архітектури та release-checks.

## 0.1.15

- До `Threats` додано `possible_threat_codes` з усіма підтримуваними кодами загроз незалежно від поточного стану.

## 0.1.14

- Виправлено міграцію старого `entity_id` після видалення та повторного додавання території.
- Старі автоматичні ID на кшталт `sensor.m_kiiv_threat_codes` коректно перетворюються на `sensor.ua_31_threats`; ручні перейменування зберігаються.

## 0.1.13

- Російські назви загроз скорочено до компактних підписів; усі комбінації перегенеровано без зміни raw-кодів.

## 0.1.12

- Додано агрегацію часткових тривог для районів та областей.
- Додано `sensor.ua_<uid>_coverage` зі стабільними кодами `none/full/partial/mixed`.
- Рівень батьківської території показує максимум усередині території, а `full_level_code` і `partial_level_code` зберігають відмінність повного та часткового охоплення.
- Додано `possible_level_codes` і `possible_coverage_codes`.

## 0.1.11

- Виправлено критичне успадкування тривог униз за адміністративним деревом: область → район → громада.
- Загрози батьківських записів успадковуються нащадками; latency рахується від реального запису джерела.
- Додано атрибути джерела тривоги та regression-тести для Обухівського району / Кагарлицької громади.

## 0.1.10

- Останні alert/threat latency зберігаються в `.storage` і відновлюються після перезапуску.
- Event latency виключено з оцінки `data_health`; `delayed` залишено лише для повільної HTTP-відповіді джерела.

## 0.1.9

- Додано `sensor.ua_<uid>_health` зі станами `normal`, `delayed`, `source_error`, `data_error`.
- Додано технічні атрибути джерела та обмеження частоти шумних діагностичних оновлень.

## 0.1.8

- Запроваджено короткі UID-based entity_id: `ua_<uid>_<suffix>`.
- `unique_id` збережено; додано безпечну міграцію незмінених старих ID.

## 0.1.7

- Вбудовано повний каталог 1607 територій.
- Додано незалежні режими **Пошук** і **Дерево**, пошук за UID та поширені/історичні aliases.
- Автоматичне оновлення каталогу прибрано; оновлення лише вручну.

## 0.1.6

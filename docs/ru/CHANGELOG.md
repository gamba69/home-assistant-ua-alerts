# История изменений

## 0.1.22
- На странице каждого устройства территории для администратора добавлена заметная кнопка **Тестирование тревоги**.
- Кнопка сразу открывает компактное окно теста этой территории: уровень тревоги и мультивыбор угроз; территорию повторно выбирать не нужно.
- Обычный переход к настройкам интеграции сохранён в меню устройства `⋮`. Семантика теста не изменилась: реальный polling и история Last Alert / задержек не загрязняются тестовой подменой.

## 0.1.21
- На каждом устройстве территории добавлены редактируемые конфигурационные `Poll interval` и `Stale after`. Значения остаются глобальными и изменение с любой территории сразу применяется ко всем entries.
- В Configure добавлено тестирование конкретной территории: `Выключено` / `Нет тревоги` / `Жёлтый` / `Красный` и мультивыбор любых поддерживаемых угроз. Подмена управляет обычными сущностями и событиями тревоги/угроз, а реальный polling и история Last Alert / задержек продолжают работать независимо.
- Устройство территории теперь ведёт на свою точную Config Entry UA Alerts, поэтому для тестирования территорию повторно выбирать не нужно.

## 0.1.20
- Диагностические `Задержка тревоги` / `Задержка угрозы` заменены обычными state-сенсорами `Задержка последней тревоги` и `Задержка последней угрозы`; entity registry мигрируется без потери накопленных измерений.
- Добавлены `Длительность последней тревоги` и `Уровень последней тревоги` — максимальный жёлтый/красный уровень последней полностью наблюдавшейся завершённой тревоги.
- Lifecycle текущей тревоги сохраняется в `.storage`, поэтому нормальная тревога переживает рестарт HA и корректно завершается по достоверному `clear`; stale/ошибки тревогу не закрывают.
- Если HA впервые стартовал уже посреди неизвестной активной тревоги, длительность и максимальный уровень для неё намеренно не выдумываются.

## 0.1.19
- Исправлены HA 2026.9 device-registry тесты после удаления `DeviceEntry.translation_key`.
- Синхронизированы версия и публичная документация; в корневой README добавлено краткое описание проекта.

## 0.1.18
- HA regression-тесты обновлены под актуальные API 2026.9; проверка версии больше не прибита к конкретному patch-релизу.
- Python-константа `VERSION` синхронизирована с manifest.

## 0.1.17
- Исправлен порядок ключей manifest для Hassfest и объявлена config-entry-only schema.
- Project tests переведены на Python 3.14; pip cache привязан к `requirements_test.txt`.

## 0.1.16

- Формулировки config flow сделаны нейтральными: вручную обновлённый сохранённый справочник больше не называется «встроенным».
- Подготовлен первый публичный GitHub/HACS-релиз без изменения рабочей семантики тревог.
- Добавлена MIT License и трёхъязычная документация `docs/en`, `docs/ru`, `docs/uk`; корневые README/CHANGELOG/ARCHITECTURE/TESTING сделаны навигационными по образцу Vacuum Schedule.
- CI разделён на `hacs.yaml`, `hassfest.yaml`, `tests.yaml`; добавлены JSON/YAML validation и запрет сгенерированных `.patch`.
- В `hacs.json` добавлен `render_readme: true`; тесты расширены проверкой публичной структуры репозитория.
- Добавлена отдельная документация по архитектуре и release-checks.

## 0.1.15

- В `Threats` добавлен `possible_threat_codes` со всеми поддерживаемыми кодами угроз независимо от текущего состояния.

## 0.1.14

- Исправлена миграция старого `entity_id` после удаления и повторного добавления территории.
- Старые автоматические ID вроде `sensor.m_kiiv_threat_codes` теперь корректно превращаются в `sensor.ua_31_threats`; пользовательские переименования сохраняются.

## 0.1.13

- Русские названия угроз сокращены до компактных: Тактическая, Стратегическая, МиГ-31К, Баллистика, Крылатые, Ракеты, БПЛА, КАБ, ПВО, Неизвестно.
- Перегенерированы все комбинации угроз; raw-коды не менялись.

## 0.1.12

- Добавлена агрегация частичных тревог для районов и областей.
- Добавлен `sensor.ua_<uid>_coverage` со стабильными кодами `none/full/partial/mixed`.
- Уровень родительской территории теперь показывает максимум внутри территории, а `full_level_code` и `partial_level_code` сохраняют смысл полного и частичного охвата.
- Добавлены `possible_level_codes` и `possible_coverage_codes`.

## 0.1.11

- Исправлено критическое наследование тревог вниз по административному дереву: область → район → громада.
- Угрозы родительских записей наследуются потомками; latency считается от реальной записи источника.
- Добавлены атрибуты источника тревоги и regression-тесты для Обухівського району / Кагарлицької громади.

## 0.1.10

- Последние alert/threat latency сохраняются в `.storage` и восстанавливаются после рестарта.
- Event latency исключена из оценки `data_health`; `delayed` оставлен только для медленного HTTP-ответа источника.

## 0.1.9

- Добавлен `sensor.ua_<uid>_health` со состояниями `normal`, `delayed`, `source_error`, `data_error`.
- Добавлены технические атрибуты источника и ограничение частоты обновления шумных диагностических деталей.

## 0.1.8

- Введены короткие UID-based entity_id: `ua_<uid>_<suffix>`.
- `unique_id` сохранены; добавлена безопасная миграция нетронутых старых ID.

## 0.1.7

- Встроен полный каталог 1607 территорий.
- Добавлены независимые режимы выбора **Поиск** и **Дерево**, UID-поиск и исторические/распространённые алиасы.
- Автоматическое обновление каталога полностью исключено; обновление только вручную.

## 0.1.6

- Добавлена отдельная `threat_latency` для новых экземпляров угроз.
- Исключены ложные измерения для угроз, уже активных при старте HA, и для простого изменения уровня той же угрозы.

## 0.1.5

- Переработана alert latency: `Alert.started_at → первое наблюдение Home Assistant` на переходе `clear → active`.
- Удалены старые высокочастотные диагностические timestamp/latency сущности.

## 0.1.4

- Имя устройства стало точным названием территории из справочника.
- Территория зарегистрирована как service device; убраны ошибочные переводы типа территории из device name/model.

## 0.1.3

- Добавлена frontend-локализация типов/состояний угроз, включая комбинации; raw-коды оставлены в атрибутах.

## 0.1.2

- Улучшена RU/UK/EN локализация и вынесены стабильные machine-коды в атрибуты.
- Удалено автоматическое обновление справочника, добавлено явное ручное обновление.

## 0.1.1

- Добавлены brand icons, иерархический выбор территории, domain-wide timing settings и расширенные тесты runtime/parser.

## 0.1.0

- Первый release candidate: token-free источник, singleton runtime, `clear/yellow/red`, угрозы, события, config flow, EN/RU/UK и HACS-ready структура.

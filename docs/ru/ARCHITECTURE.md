# Архитектура

## Общая схема

UA Alerts построена вокруг **одного runtime на весь domain** и отдельных лёгких coordinator для каждой выбранной территории. Количество Config Entry не увеличивает количество запросов: один raw snapshot загружается и разбирается один раз, затем используется всеми территориями.

## Основные модули

- `runtime.py` — единый HTTP polling loop, сериализация запросов, свежесть источника и общий parsed snapshot.
- `models.py` — валидация/разбор источника и чистая логика тревог, угроз, иерархии и latency.
- `coordinator.py` — вычисляет состояние одной территории, отслеживает переходы и публикует обновления/события HA.
- `sensor.py`, `binary_sensor.py` — сущности Home Assistant.
- `catalog.py`, `catalog_parser.py`, `catalog_search.py` — встроенный справочник, ручное обновление, поиск и дерево.
- `config_flow.py` — добавление территории и общие настройки polling/stale.
- `latency_storage.py` — сохранение последнего измерения задержки тревоги и угрозы по UID.
- `health.py` — компактное состояние качества данных.
- `entity_ids.py` — короткие UID-based entity_id и безопасная миграция старых автоматических имён.

## Жизненный цикл runtime

Первая Config Entry создаёт `UAAlertsRuntime`, остальные регистрируются в том же экземпляре. Последняя выгруженная Entry останавливает runtime. Отдельные asyncio-lock защищают lifecycle и HTTP-запросы, поэтому параллельных polling loop и одновременных fetch нет.

Успешный цикл делает один GET, валидирует payload, фиксирует единый `received_at`, один раз парсит raw, атомарно заменяет общий snapshot и уведомляет все coordinators.

Ошибка опроса не означает `clear`: последний валидный snapshot сохраняется до превышения stale timeout.

## Административная иерархия

Наследование вниз является прямым: тревога области действует на её районы и громады, тревога района — на его громады. Для громады учитываются собственный UID + район + область. Для района собственный UID + область определяют полное покрытие.

Агрегация вверх имеет другую семантику: тревога одной громады не делает весь район полностью тревожным. Для районов и областей активность дочерних территорий формирует **частичный охват**. Сенсор охвата имеет состояния `none`, `full`, `partial`, `mixed`, а сенсор уровня показывает максимальный уровень где-либо внутри выбранной территории.

## Уровни и угрозы

Учитываются только активные записи `air_raid`. `alert_level` обязан быть `yellow` или `red`; уровень не выводится из текста или временных полей. При нескольких применимых записях действует приоритет `red > yellow`.

Угрозы со всех применимых full/partial записей объединяются и дедуплицируются. Известные коды локализуются для интерфейса, сырые коды сохраняются в атрибутах. Неизвестный будущий код не отбрасывается.

## Семантика latency

Задержка тревоги измеряется только после валидного baseline и на реальном переходе `clear -> active`:

`Alert.started_at -> received_at первого snapshot, где HA увидел тревогу`.

Задержка угрозы измеряется для нового экземпляра `(threat_type, started_at)`:

`Threat.started_at -> received_at первого snapshot с этой угрозой`.

Значения фиксируются, сохраняются по UID и восстанавливаются после рестарта. Если HA стартует во время уже активной тревоги/угрозы, это создаёт baseline, а не ложную огромную задержку.

## Идентичность сущностей

Entity ID строятся по стабильному UID территории, например `sensor.ua_31_level`. `unique_id` не меняются между релизами. Миграция сокращает только нетронутые старые автоматические ID и сохраняет ручные переименования. Повторная миграция после создания платформ обрабатывает старые ID, восстановленные Home Assistant из deleted registry.

## Политика справочника

В пакет входит полный snapshot справочника. Автоматического обновления нет. Обновление запускается вручную из options flow; ошибка не заменяет последнюю валидную сохранённую версию.

## Ошибки и диагностика

Операционные сущности становятся unavailable при stale источнике или невалидных данных выбранной территории. `data_health` остаётся доступным и показывает `normal`, `delayed`, `source_error`, `data_error`. `delayed` относится только к медленному HTTP-ответу; end-to-end задержки тревог и угроз являются измерениями и сами по себе не считаются ошибкой.

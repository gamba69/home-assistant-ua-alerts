# UA Alerts

UA Alerts — пользовательская интеграция Home Assistant для уровней воздушной тревоги в Украине с состояниями `clear`, `yellow`, `red`, угрозами, охватом территории и измерением лага появления событий в Home Assistant.

Источник данных — токен-независимый raw-поток `alerts.in.ua` через Ubilling:

`https://ubilling.net.ua/aerialalerts/?source=aiu&raw`

## Идентификаторы проекта

- Название: **UA Alerts**
- Domain: `ua_alerts`
- Каталог интеграции: `custom_components/ua_alerts/`
- Репозиторий: `gamba69/home-assistant-ua-alerts`
- Текущий релиз: **0.1.23**

## Основные возможности

- одна Config Entry на территорию, одновременно можно добавить несколько территорий;
- единый runtime на весь domain: один HTTP-запрос и один разбор ответа на цикл независимо от количества территорий;
- настраиваемые глобальные интервалы polling/stale, по умолчанию 3 с / 15 с;
- уровни тревоги берутся только из `alert_level` источника;
- корректная административная иерархия `область → район → громада`;
- для районов и областей различается полный, частичный и смешанный охват тревоги;
- угрозы объединяются и дедуплицируются по применимым уровням иерархии;
- отдельные компактные end-to-end измерения лага тревоги и новой угрозы;
- EN / RU / UK локализация;
- полный встроенный справочник территорий и ручное, а не автоматическое, обновление;
- короткие стабильные entity_id на базе UID территории;
- HACS-ready структура репозитория.

## Установка

### Через HACS как custom repository

1. Добавьте `gamba69/home-assistant-ua-alerts` в HACS как пользовательский репозиторий категории **Integration**.
2. Установите **UA Alerts**.
3. Перезапустите Home Assistant.
4. Откройте **Настройки → Устройства и службы → Добавить интеграцию** и найдите **UA Alerts**.
5. Выберите территорию через **Поиск** или **Дерево**.

### Вручную

Скопируйте `custom_components/ua_alerts/` в `/config/custom_components/ua_alerts/`, перезапустите Home Assistant и добавьте интеграцию через интерфейс.

## Выбор территории

Во встроенном пакете находится снимок справочника из 1607 территорий: 25 территорий уровня области, 122 района, 1458 громад и два города со специальным статусом. Поиск принимает название, ряд распространённых/исторических вариантов и UID `alerts.in.ua`. Дерево позволяет выбрать область/город, затем уровень, район и громаду.

Каталог **никогда не обновляется автоматически**. Обновление запускается только пользователем через **Настроить → Обновить справочник территорий**. Успешно загруженная версия сохраняется локально; ошибка обновления не уничтожает последнюю валидную копию.

## Административное наследование и частичный охват

Тревога на родительской территории действует на всех потомков. Поэтому выбранная громада проверяет собственный UID, UID района и UID области; выбранный район — собственный UID и UID области. Максимальный применимый уровень побеждает: `red > yellow > clear`.

Обратное направление не трактуется как полная тревога. Если тревога есть только в одной громаде, весь район не становится «полностью красным». Для районов и областей используется отдельный сенсор охвата:

- `none` — тревоги нет;
- `full` — тревога действует на всю выбранную территорию;
- `partial` — активна только часть дочерних территорий;
- `mixed` — вся территория имеет один уровень, а часть дочерних территорий — более высокий.

Например, район целиком `yellow`, а одна громада `red`: итоговый уровень района — `red`, охват — `mixed`, `full_level_code=yellow`, `partial_level_code=red`.

## Сущности

Для громады/города создаются одиннадцать сущностей, включая два редактируемых глобальных параметра; для района/области — двенадцатая сущность охвата:

| Entity ID | Назначение |
| --- | --- |
| `sensor.ua_<uid>_level` | Уровень тревоги; в атрибутах только scope и читаемый источник территории |
| `sensor.ua_<uid>_coverage` | Только район/область: охват `none/full/partial/mixed` и `full_level_code` / `partial_level_code` |
| `binary_sensor.ua_<uid>_alert` | Активна ли воздушная тревога |
| `sensor.ua_<uid>_threats` | Активные `threat_codes` и подробный список `threats` |
| `binary_sensor.ua_<uid>_source` | Доступность/свежесть источника |
| `sensor.ua_<uid>_last_alert_duration` | Длительность в компактном `MM:SS`, `H:MM:SS` или `Dд HH:MM:SS`; секунды в `duration_seconds` |
| `sensor.ua_<uid>_last_alert_level` | Максимальный уровень последней полностью наблюдавшейся завершённой тревоги |
| `sensor.ua_<uid>_last_alert_lag` | Лаг начала последней новой тревоги до первого наблюдения HA |
| `sensor.ua_<uid>_last_threat_lag` | Лаг появления последней новой угрозы до первого наблюдения HA |
| `sensor.ua_<uid>_health` | Сводное состояние данных |

Стабильные коды уровня: `clear`, `yellow`, `red`. Коды охвата: `none`, `full`, `partial`, `mixed`.

Поддерживаемые коды угроз: `tactic_aircraft_activity`, `strategic_aircraft_activity`, `mig31k_departure`, `ballistic_missiles`, `cruise_missiles`, `unspecified_missiles`, `drones`, `guided_aerial_bombs`, `air_defense`, `unknown`.

Русские короткие подписи: **Тактическая, Стратегическая, МиГ-31К, Баллистика, Крылатые, Ракеты, БПЛА, КАБ, ПВО, Неизвестно**.

## Лаг

`last_alert_lag` измеряется только при валидном переходе `clear → yellow/red` как разница между `Alert.started_at` и временем первого snapshot, где Home Assistant увидел новую тревогу. `last_threat_lag` аналогично измеряет новую угрозу по `Threat.started_at`. Значения фиксируются и сохраняются в `.storage`.

От 1 секунды лаг показывается целыми секундами; ниже секунды — с точностью до двух знаков. Это измерения, а не оценка качества источника, поэтому они не переводят `health` в `delayed`.

Лишние атрибуты убраны: уровень тревоги больше не дублирует собственное значение/possible-коды/UID; охват оставляет только `full_level_code` и `partial_level_code`; угрозы — только `threat_codes` и `threats`. У `last_alert_level` собственных атрибутов нет.

## События

Интеграция публикует:

- `ua_alert_level_changed`;
- `ua_alert_threats_changed`;
- `ua_alert_source_availability_changed`.

## Отказы источника

Ошибка одного опроса не означает `clear`: последний валидный snapshot сохраняется. После превышения stale timeout операционные сущности становятся unavailable, а `source_available` выключается. Первый успешный опрос восстанавливает работу.
